# Data sources and refresh lifecycle

This directory contains versioned public-data artifacts. It is not a replacement for Supabase account data. Do not store credentials or private user records here.

## Runtime sources

| Source | Used for | Retrieval and caching |
| --- | --- | --- |
| [Sleeper public API](https://docs.sleeper.com/) | NFL season/week, league settings/users/rosters, player metadata, matchups, drafts/traded picks | Public browser and server reads. Ownership is revalidated before actions; trade inventory is not cached. Current-season resolution is cached 10 minutes in the stats route. |
| Sleeper `/projections/nfl/...` | Weekly and season projection components | Next server route; 15-minute weekly / 6-hour season upstream and shared caches. League-specific score conversion. |
| [ESPN fantasy API](https://lm-api-reads.fantasy.espn.com/apis/v3/games/ffl/seasons/2026/segments/0/leaguedefaults/3?view=kona_player_info) | Current regular-season actual PPR totals and games played | `/api/roster-stats` selects current-season `statSourceId=0`, season-total rows only. Default league 3 supplies PPR scoring. Full NFL position ranks are calculated server-side. The normalized map is cached 15 minutes; raw payload is not delivered to the browser. The season in this example URL is illustrative; code resolves it dynamically. |
| ESPN site API / CDN | Schedule, NFL and college portraits/logos | Public schedule reads and image URLs. The app uses stored cutouts where supplied. |
| Supabase `dynasty_prospects` | Prospect identity, original grade, college production and class | `/api/prospects`, 5-minute shared cache. History uses a past-class filter and pagination; future curated rows are excluded. |
| ESPN college athlete statistics | 2027 class passing, rushing, and receiving career totals | `refresh-college-prospects.py` checks stored ESPN IDs against athlete names and imports current-season totals three times weekly. Scouting grades and ranks are not recalculated. The provider does not supply an observation timestamp, so health reports check time and coverage separately. |
| Supabase KTC history + `ktc-history.json` | Market values, trend/sparklines | Server normalization and paginated history reads; bundled fallback when DB is unavailable. Coverage metadata identifies source/date. |

The ESPN API is undocumented. [Public-ESPN-API](https://github.com/pseudo-r/Public-ESPN-API) is an endpoint reference, not the data provider. Schema/status failures must surface as unavailable data rather than silently reusing a different season. The application currently uses standard PPR for actual FPPG; custom league scoring is applied to projections, not these ESPN actual totals.

## Versioned datasets

### `history-outcomes.json`

Generated by `scripts/import-history-outcomes.py` from:

- [Fantasy Football Calculator rookie ADP API](https://help.fantasyfootballcalculator.com/article/42-adp-rest-api): 12-team historical average rookie draft position, draft observation counts and archive windows.
- [nflverse player statistics](https://nflreadr.nflverse.com/reference/load_player_stats.html): regular-season weekly fantasy PPR production, legacy archive through 2024 and yearly `stats_player` releases thereafter.
- [dynastyprocess player IDs](https://github.com/dynastyprocess/data/blob/master/files/db_playerids.csv): GSIS, ESPN, Sleeper identity and NFL entry-year crosswalk.

The importer rejects incorrect archive years, ambiguous ADP identities, in-season ADP windows after September 6, duplicate player/week statistics, incomplete league-wide week coverage and backward-moving production cutoffs. During the regular season it includes completed weeks only. Original grades and live KTC values are not inputs to the outcome model.

Initial coverage is through 2026 Week 6, with 2,695 NFL identities and 377 matched ADP records. Usable ADP years are 2014, 2016–2023 and 2025. 2024/2026 contain no players in the source archive; 2015's observation window is rejected. Sparse cohorts and missing data remain gray. See the [versioned methodology](../docs/history-outcomes-plan.md) before changing thresholds.

The server computes the five-bar result and serves compact keyed outcomes. The client does not download the full weekly-stat snapshot. An API cache refresh cannot make an old bundled snapshot newer; a newly generated dataset must be deployed.

### `nfl-player-identities.json`

Compact Sleeper → ESPN ID crosswalk from dynastyprocess. Many live Sleeper player records now have null ESPN/GSIS IDs. The stats route uses this stable mapping; it does not guess identities using player names. Unknown mappings stay unavailable. The History importer also refreshes this file.

### `ktc-history.json`

Validated compact archive imported from [`cameron-eth/sleeper-sdk`](https://github.com/cameron-eth/sleeper-sdk). The daily workflow uses the SDK scraper, imports complete history, idempotently upserts Supabase by player/date and proposes an updated bundled fallback. No deletes are performed during import. Heat combines KTC momentum and recent completed-game PPR momentum; it is not the number of trade requests. [Heat details](../docs/sleeper-connections.md).

## Refresh commands and jobs

From `firstballot/`:

```sh
python3 scripts/import-history-outcomes.py
# Optional cache directory override: OUTCOME_CACHE_DIR=/path/to/cache

python3 scripts/import-ktc-history.py /path/to/sleeper-sdk/data/ktc data/ktc-history.json
node scripts/sync-ktc-values.mjs
```

| Workflow | Schedule (UTC) | Persistent effects |
| --- | --- | --- |
| `.github/workflows/history-outcomes.yml` | Wednesday 12:20 | Validates and proposes a PR for outcome + identity snapshots; does not automatically merge or deploy them |
| `.github/workflows/ktc-history.yml` | Daily 10:30 | SDK scrape, full archive import, Supabase upsert and fallback snapshot PR |
| `.github/workflows/college-prospects.yml` | Monday, Wednesday, Friday 11:45 | Validates 2027 ESPN athlete identities and season coverage, updates matched college totals, and stores a 7-day check snapshot. Missing or ambiguous athletes remain unchanged and are counted. |

Both support manual dispatch and run scheduled jobs only once present on the default branch. They require GitHub contents/pull-request write permissions. KTC persistence also needs repository secrets `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Public history ingestion does not require Supabase credentials.

## Not stored here

Saved plans, boards, notes, ballots and encrypted Sleeper connections belong to authenticated Supabase tables/private buckets. Selection caches and dismissals can live in browser storage. See the [application persistence matrix](../README.md#persistence-and-privacy-boundaries) for the exact split.
